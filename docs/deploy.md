# Развёртывание

Приложение работает в одном контейнере: собранный сайт, API, HR-панель и боты. Рядом стоит PostgreSQL 16. Всё хранится и работает в России.

## Где разместить

Подойдёт любой российский облачный провайдер с Docker и управляемым PostgreSQL:

| Провайдер | Приложение | База |
|---|---|---|
| Yandex Cloud | виртуальная машина с Docker или Serverless Containers | Managed Service for PostgreSQL |
| Selectel | облачный сервер с Docker | облачные базы данных PostgreSQL |
| VK Cloud | виртуальная машина с Docker | облачная PostgreSQL |

Cloudflare и зарубежные CDN у российских провайдеров работают с перебоями, поэтому все ассеты (шрифты, фото, скрипты) уже собраны в образ и отдаются самим сервером.

## Первый запуск на сервере

**Одной командой на чистой Ubuntu 22.04** (стенд antihype.best так и поднят): Docker, проект с GitHub, база, сайт и HTTPS через Caddy. Скрипт спросит ключ GigaChat, сам создаст пароль базы и вход в HR-панель и в конце покажет их. Повторный запуск обновляет проект, `.env` и база остаются.

```bash
curl -fsSL https://raw.githubusercontent.com/3r0ha/Ochakovo/main/scripts/server-setup.sh | bash
```

Домен и папку можно поменять: `DOMAIN=example.ru DIR=/opt/site bash server-setup.sh`. Дальше то же самое по шагам.

```bash
git clone <репозиторий> && cd ochakovo
cp .env.example .env              # заполнить, см. таблицу ниже: SITE_URL, HR_ADMIN_*, база
sh scripts/max-cert.sh            # сертификат Минцифры, нужен для MAX и GigaChat
```

Дальше выберите один из двух вариантов базы.

**Управляемая база провайдера** (так надёжнее: копии и обновления делает провайдер). В `.env` задайте `APP_DATABASE_URL=postgres://…` и запустите только сервер:

```bash
docker compose up -d --build
curl -s localhost:8787/api/health/ready  # status: ready
```

**База в контейнере рядом с сервером**, профиль `local-db`. В `.env` задайте `POSTGRES_PASSWORD` (значения по умолчанию нет; без `@`, `:`, `/` и пробелов, потому что он попадает в адрес базы):

```bash
docker compose --profile local-db up -d --build
curl -s localhost:8787/api/health/ready
```

Если не задано ни `APP_DATABASE_URL`, ни `POSTGRES_PASSWORD`, compose остановится с сообщением «задайте в .env APP_DATABASE_URL … или POSTGRES_PASSWORD …». Проверить, что получится, не запуская контейнеры: `docker compose config` покажет у `app` нужный `DATABASE_URL`, а без профиля `local-db` сервиса `db` в выводе нет.

Порты сервера и базы открыты только на этой машине (`127.0.0.1`), наружу сайт выходит через HTTPS-прокси (следующий раздел). Другой порт сервера задаёт `APP_PORT`, базы `POSTGRES_PORT`.

Миграции применяются сами при старте (`server/db/migrations`). Если база недоступна, сервер пишет её адрес без пароля и подсказку и завершается с кодом 1.

## HTTPS и прокси

Сервер слушает HTTP на порту 8787. Снаружи нужен HTTPS через балансировщик облака или nginx/Caddy на той же машине:

```nginx
server {
  listen 443 ssl http2;
  server_name season.ochakovo.ru;
  # ssl_certificate … ssl_certificate_key …
  client_max_body_size 2m;
  location / {
    proxy_pass http://127.0.0.1:8787;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
  }
}
```

За прокси обязательно задайте `TRUST_PROXY=1` (число прокси перед сервером; `true` и `yes` тоже значат один прокси), иначе лимиты запросов будут считать всех посетителей одним адресом. Повтор заявки (409 за 10 минут) и лимит три заявки в час (429 `phone_limit`) считаются по телефону или нику: с одного Wi-Fi на ярмарке заявки разных людей проходят. HSTS включается сам, когда `NODE_ENV=production` и `SITE_URL` или `PUBLIC_URL` начинаются с `https://`.

## Домен antihype.best

Стенд команды: машина `45.132.177.48` (Ubuntu 22.04, порты 22, 80 и 443 открыты), вход `ssh ochakovo`. Сертификат выпускает Let's Encrypt через Caddy, для этого домен должен смотреть на машину, а порты 80 и 443 быть открыты.

Записи у регистратора домена:

| Тип | Имя | Значение | Зачем |
|---|---|---|---|
| A | `@` | `45.132.177.48` | сам antihype.best |
| A | `www` | `45.132.177.48` | www.antihype.best, Caddy перенаправит на адрес без www |
| CAA | `@` | `0 issue "letsencrypt.org"` | сертификат для домена может выпустить только Let's Encrypt; запись не обязательна |

TTL подойдёт 300 секунд, чтобы правки расходились быстро. Записей AAAA быть не должно: у машины нет IPv6, а Let's Encrypt проверяет IPv6 первым, если запись есть. Если регистратор поставил свои A или AAAA для страницы-заглушки, их нужно удалить. Проверить, что записи разошлись: `dig +short antihype.best` и `dig +short www.antihype.best` должны вернуть `45.132.177.48`.

Caddy на машине (`/etc/caddy/Caddyfile`):

```
www.antihype.best {
  redir https://antihype.best{uri} permanent
}

antihype.best {
  reverse_proxy 127.0.0.1:8787
}
```

В `.env` для этого домена: `SITE_URL=https://antihype.best`, `PUBLIC_URL=https://antihype.best` (нужен для вебхуков ботов) и `TRUST_PROXY=1`.

| `PORT` | нет | порт сервера, по умолчанию 8787 |
| `DIST_DIR` | нет | другая папка собранного сайта вместо `dist/`: своя сборка рядом с рабочей (`vite build --outDir …`) |

## Боты и вебхуки

Без `PUBLIC_URL` боты сами опрашивают API мессенджера, а маршруты `/bots/telegram` и `/bots/max` отвечают 403.

С заданным `PUBLIC_URL` сервер при старте сам регистрирует вебхуки. Вебхук работает только с секретом: если `TELEGRAM_WEBHOOK_SECRET` или `MAX_WEBHOOK_SECRET` пусты, сервер при каждом запуске создаёт случайный секрет (32 байта) и передаёт его мессенджеру вместе с адресом. В журнале появляется строка «секрет вебхука сгенерирован», сам секрет туда не попадает. Если серверов несколько, задайте секрет явно (от 32 знаков: латиница, цифры, `_` и `-`), иначе у каждого будет свой. Неверный по формату секрет не даёт поднять адаптер: он виден в готовности (`botsFailed`).

Запрос без верного секрета получает 403; после 30 отклонённых запросов в минуту с одного адреса сервер отвечает 429. Верные апдейты мессенджера лимит не задерживает. Telegram принимает только личный чат с отправителем и только его собственный контакт: апдейт из группы или чужой номер до движка диалогов не доходят.

- Telegram: `PUBLIC_URL/bots/telegram`, секрет приходит в заголовке `X-Telegram-Bot-Api-Secret-Token`. Порты для вебхука у Telegram: 443, 80, 88 или 8443.
- MAX: `PUBLIC_URL/bots/max`, секрет в `X-Max-Bot-Api-Secret`. Только HTTPS на 443 с сертификатом от доверенного центра (сертификаты Минцифры подходят), полная цепочка обязательна.

Бота в MAX может завести только самозанятый, ИП или компания, модерация занимает до 48 рабочих часов. Код адаптера готов, бот включается, когда «Очаково» получит токен.

### Telegram: профиль, мини-приложение и доступ из России

Тестовый бот команды: [@kvasantihypebot](https://t.me/kvasantihypebot). Токен не хранится в репозитории, его задают в `.env` (`TELEGRAM_BOT_TOKEN`, `TELEGRAM_BOT_USERNAME=kvasantihypebot`).

При каждом запуске сервер сам ставит профиль бота: меню команд (`/start`, `/menu`, `/help`, `/stop`, `/delete`), короткое и полное описание и кнопку «Игры» у поля ввода. Кнопка открывает мини-приложение `SITE_URL/play`, только если `SITE_URL` начинается с `https://`, иначе у поля ввода остаётся меню команд. Если Telegram не принял профиль, бот всё равно работает, в журнале будет предупреждение.

Мини-приложение сделано из страницы сайта `/play`, где игры идут по одной на экран. Бот предлагает их кнопками web_app в меню («Игры во весь экран») и во вступлениях к «Поймай брак», «Собери лето» и викторине. В MAX те же кнопки открывают страницу ссылкой. Внутри Telegram страница разворачивается на весь экран, красит шапку в цвет сайта, не закрывается свайпом вниз и прячет чат сайта: человек и так в чате с ботом. Данные Telegram из адреса страница сразу стирает и никуда не отправляет. Telegram Web открывает мини-приложение во фрейме, поэтому страницам кандидата разрешено встраивание только в `https://web.telegram.org` (`frame-ancestors`); HR-панель и API не встраиваются никуда.

Что сделать руками в [@BotFather](https://t.me/BotFather):
- аватарка: `/setuserpic`, файл `docs/brand/bot/avatar.png` (640 × 640, запасной вариант на тёмном фоне `avatar-dark.png`);
- кнопка «Открыть» в профиле бота: Bot Settings → Configure Mini App → адрес `https://antihype.best/play?src=telegram`. Необязательно, кнопка «Игры» у поля ввода работает и без этого.

В России Telegram заблокирован, и сервер в российском облаке не достучится до `api.telegram.org`. Варианты:
- поднять второй экземпляр сервера только для бота там, где Telegram доступен, с той же базой (`APP_DATABASE_URL`);
- оставить сервер в России, задать `TELEGRAM_API_BASE` (адрес своего прокси Bot API за рубежом, который передаёт запросы на `api.telegram.org`) и не задавать `PUBLIC_URL`. Тогда бот сам опрашивает Telegram через прокси, а входящие соединения из-за рубежа не нужны. Вебхук здесь не подходит: Telegram шлёт его со своих зарубежных серверов, а облако стенда входящие из-за рубежа не пропускает.

## Сертификат Минцифры

API MAX и GigaChat используют сертификат «Russian Trusted Root CA». `scripts/max-cert.sh` скачивает его в `certs/`, Docker-образ подхватывает его сам (`NODE_EXTRA_CA_CERTS`). При запуске без Docker:

```bash
NODE_EXTRA_CA_CERTS=certs/russian_trusted_root_ca.pem pnpm server:start
```

## Проверки здоровья

| Путь | Для чего |
|---|---|
| `/api/health/live` | процесс жив; если нет, контейнер перезапускают |
| `/api/health/ready` | можно направлять трафик: база отвечает, движок диалогов загружен, ни один включённый бот не упал. Иначе 503, и в ответе сказано, что именно: `db`, `engine`, `botsFailed` |
| `/api/health` | для людей: версия, база, боты (`bots` работают, `botsFailed` заданы, но не поднялись), режим помощника. В `ops` лежат данные для эксплуатации, только время и числа, без текстов ошибок. `jobs.failed24h`: сообщения кандидатам, которые за сутки исчерпали три попытки. `jobs.stuck`: задачи, которые созрели больше 10 минут назад и не взяты. `disk`: последняя удачная выгрузка на Яндекс Диск и была ли ошибка после неё (сам текст в панели, «Интеграции»). `retention.lastRunAt`: последний проход срока хранения. `botsLastSeen`: последнее сообщение от людей в Telegram и MAX. `lastExport`: последняя выгрузка из журнала выгрузок. Сводка обновляется раз в 30 секунд |

Docker-образ сам проверяет `/api/health/live` каждые 30 секунд. Бот, который не поднялся (неверный токен, ошибка модуля), не роняет сервер: сайт и HR-панель работают, а готовность честно отвечает 503, пока бота не починят.

## Журналы

Сервер пишет журнал в stdout строками JSON: время, номер запроса, метод, путь, статус, длительность. IP, тела запросов и параметры не пишутся, потому что в них бывают персональные данные и токены. Номер запроса приходит в заголовке ответа `X-Request-Id`, по нему удобно искать проблему.

При запуске сервер пишет одну строку `"msg":"startup"` о том, что включено: режим, `SITE_URL`, есть ли собранный сайт, движок диалогов, боты (`bots`, `botsFailed`, `botsVia`: вебхук или опрос), помощник (`gigachat` или `offline`), Яндекс Диск, SMS, hh.ru, срок хранения в месяцах, `TRUST_PROXY`. Секретов в ней нет.

```bash
docker compose logs app | grep '"msg":"startup"'
docker compose logs -f app | grep '"level":"error"'
```

Журнал выгрузок (таблица `access_log`) хранит, кто, с какой ролью и когда забрал данные (файл из панели, выгрузка на Яндекс Диск, чтение служебным токеном), формат, число строк, отбор и номера заявок. Самих данных в нём нет; по номеру заявки видно, кому и когда ушли данные кандидата. Хранится столько же, сколько заявки (`RETENTION_MONTHS`).

## Срок хранения и журнал удаления

Политика обработки данных обещает хранить заявку сезон и ещё 12 месяцев. Сервер исполняет это сам: раз в сутки (первый раз вскоре после запуска) планировщик обезличивает всё, что не менялось дольше `RETENTION_MONTHS` месяцев:

- в заявках стираются имя, фамилия, отчество, телефон, контакты, дата рождения, учёба, друг, портфолио и резюме, комментарии и заметки, тексты сообщений, привязка к боту, адрес и «что взять» у собеседования. Вакансия, месяцы, источник, статусы и даты остаются, поэтому воронка и отчёты не ломаются;
- строка пользователя бота (канал и id в мессенджере, имя, ник, подписка «Напомнить о наборе») удаляется целиком, если он не заходил дольше срока. На её место встаёт обезличенная строка-счётчик: канал, метка источника, час прихода и случайный id, так что «Пришли» в воронке и аудитория по каналам за прошлые периоды не меняются. Старые диалоги с ботом удаляются;
- вопросы к Квасычу старше срока удаляются: в тексте вопроса бывают личные данные.

Всё, что удалено или обезличено, записывается в журнал удаления: когда, что, сколько, кто (для автоматического прохода «автоматически») и причина. Персональных данных в журнале нет. Журнал и кнопка «Проверить сейчас» лежат в HR-панели, «Настройки» → «Срок хранения» (видит администратор).

Удалить данные по запросу кандидата можно сразу, в его карточке: HR видит, какие заявки и профили ботов того же человека будут стёрты, и указывает причину. Это тоже попадает в журнал удаления.

Кандидат может удалить данные и сам, без звонка в отдел:

- на сайте кнопкой «Отозвать согласие и удалить заявку» в «Моей заявке» (`POST /api/applications/:id/withdraw` с ключом заявки из браузера в заголовке `x-status-token`). Заявка обезличивается сразу, задачи по ней (сообщения, напоминания) снимаются, ключ и ссылка на бота перестают работать; с чужим ключом сервер отвечает 404;
- в боте командой «Удалить мои данные»: заявки этого чата и привязанные к нему заявки с сайта обезличиваются, строка аудитории удаляется так же, как по сроку.

В журнале удаления у таких записей «Кандидат» вместо имени сотрудника (вид `candidate`; у удаления по сроку `auto`, по запросу через HR `request`).

Резервные копии храните не дольше этого срока. Копии «Заявки ГГГГ-ММ-ДД.xlsx» в «Архиве» на Яндекс Диске собираются без ФИО, телефонов, контактов, даты рождения, учёбы и свободного текста, а старше срока хранения удаляются сами. Рабочий файл «Заявки.xlsx» перезаписывается при каждой выгрузке и содержит всё, что видит отдел.

## Резервные копии

```bash
pnpm db:backup                     # backups/ochakovo-<время>.dump, старше 14 дней удаляются
pnpm db:restore -- backups/ochakovo-<время>.dump
```

Для базы в Docker (профиль `local-db`): `docker compose --profile local-db exec -T db pg_dump -U ochakovo -Fc ochakovo > backups/ochakovo.dump`. Копии лучше раз в сутки увозить в объектное хранилище провайдера (Yandex Object Storage, Selectel S3), например по cron:

```cron
0 4 * * * cd /srv/ochakovo && DATABASE_URL=… sh scripts/backup.sh
```

У управляемых баз провайдеров есть свои автоматические копии, включите их тоже.

## Сжатие и кэш

`vite build` кладёт рядом с каждым текстовым файлом сборки копии `.br` и `.gz` (плагин в `vite.config.ts`). Сервер отдаёт готовую копию по заголовку `Accept-Encoding`, на лету ничего не жмёт. JSON API и `index.html` для внутренних страниц сжимаются gzip на лету. Nginx перед сервером уже сжатые ответы не трогает, отдельно включать в нём gzip не нужно.

| Что | Cache-Control |
|---|---|
| `/assets/*` (имя с хешем) | `public, max-age=31536000, immutable` |
| `index.html` и страницы сайта | `no-cache` |
| фото, логотипы, прочие файлы из `public/` | `public, max-age=604800` |
| материалы кейса `/materials/*`: макеты, принты, превью, презентация | `no-cache`: браузер сверяется с сервером и сразу видит правки |
| ролики и постеры `/video/*` | `public, max-age=2592000, no-transform`; с `?v=<версия>` год и `immutable` |

Ролики «Смена изнутри» (`public/video/*.mp4`, их готовит `node scripts/media.mjs video`) сервер отдаёт сам, кусками по заголовку `Range`: Safari и iPhone сначала просят `bytes=0-1` и без ответа 206 ролик не играют. Ответ идёт как `video/mp4`, `Accept-Ranges: bytes`, без сжатия; за пределами файла сервер отвечает 416, на повторный запрос из кэша 304 по `ETag`. Nginx перед сервером заголовок `Range` пропускает сам, отдельной настройки не нужно. В Docker-образе ролики лежат одной копией в `dist/video`; сборка образа падает, если их там нет. Бюджет: 720p до 4 МБ, 480p до 2 МБ, вся папка до 20 МБ.

Замер главной под троттлингом медленного 4G (задержка 150 мс, 1,6 Мбит/с, процессор в 4 раза медленнее): `pnpm perf http://localhost:8787`. Скрипт печатает LCP, переданный объём и самую долгую задачу, а в поле `hr` замер панели с 5000 синтетических заявок: первая отрисовка списка (цель до 1 с), отклик поиска (до 100 мс) и опрос «ничего не поменялось» с ответом 304 (до 5 КБ). Только панель: `PERF_ONLY=hr pnpm perf http://localhost:8787`, ответы `/api/hr/*` подменяются в браузере, вход не нужен.

Главная предзагружает фото первого экрана (`<link rel="preload">` в `index.html`). На остальных страницах сервер эту ссылку убирает. Страницы сервер собирает при старте и сразу сжимает brotli на максимальном уровне. Если в `src/home/Hero.tsx` поменяется фото или его `sizes`, поправьте ссылку.

Шрифты: из наборов fontsource подключены только кириллица и латиница (`src/fonts.css`). Знаки ₽, ← → и ≈ берутся из крошечных подмножеств Onest в `src/fonts/`. Если в текстах появится новый редкий знак, добавьте его в `scripts/fonts-subset.py` и пересоберите подмножества: `python3 scripts/fonts-subset.py`.

## Превью ссылок, robots.txt и карта сайта

Ссылка на сайт в мессенджере показывает картинку и текст своей страницы. Сервер подставляет в `index.html` свои `title`, `description`, `og:*` и `twitter:card` для `/`, `/vacancies`, `/game` и `/apply`; адреса картинок и `canonical` абсолютные, от `SITE_URL`. Суммы и число вакансий берутся из `shared/content/vacancies.ts`, срок ответа HR из `shared/candidateStatus.ts`. Остальные страницы получают превью главной, панель HR ещё и `noindex`.

Картинки 1200×630 лежат в `public/og/` (главная, вакансии, «Поймай брак»), иконка для экрана «Домой» в `public/apple-touch-icon.png`. Их рисует `node scripts/og.mjs` шрифтами сайта; запускать после правки сумм, числа вакансий, графика, адреса или длины игры. Числа, из которых нарисованы картинки, записываются в `public/og/og.json`. После правки данных картинки перерисовывают. В адрес картинки сервер добавляет её хеш (`?v=…`): мессенджеры кэшируют превью по адресу и после перерисовки возьмут новую.

`/robots.txt` закрывает от поиска `/hr`, `/api/` и `/bots/` (`public/robots.txt`); строку `Sitemap:` с адресом от `SITE_URL` сервер дописывает сам. `/sitemap.xml` перечисляет публичные страницы.

**Материалы кейса.** Страница `/materials` сделана для экспертов и согласования, в меню и карте сайта её нет. Макеты листовок, стенда, мерча, обложки роликов и презентация лежат в `docs/brand/`; при сборке плагин `materials` из `vite.config.ts` копирует их в `dist/materials/` и переписывает пути к `public/` на корень сайта. В образ они попадают: `.dockerignore` отрезает `docs/`, кроме `docs/brand` без файлов `.md`. Если папки нет, сборка не падает, просто страница останется без макетов.

Проверить превью без мессенджера:

```bash
curl -s https://season.ochakovo.ru/vacancies | grep -o '<meta property="og:[a-z:]*" content="[^"]*"'
```

## Перед запуском: проверка юристом

Страница `/privacy` написана как готовая политика, без пометок «черновик», но до запуска её должен прочитать юрист «Очаково»:

- реквизиты оператора взяты из ЕГРЮЛ: АО МПБК «Очаково», ИНН 7729101200, ОГРН 1027739613791, адрес с сайта ochakovo.ru;
- срок хранения: на странице написано «сезон и ещё 12 месяцев». Сервер обезличивает старые данные сам раз в сутки и ведёт журнал удаления (раздел «Срок хранения и журнал удаления»); юристу стоит сверить список стираемых полей;
- текст согласия и возраст 18+;
- обработчики по поручению: GigaChat (ПАО Сбербанк) для помощника. Яндекс 360 для бизнеса страница называет, только когда включена выгрузка на Диск (задан `YANDEX_DISK_TOKEN` или `YANDEX_DISK_REFRESH_TOKEN`, см. `GET /api/privacy`). Нужны ли с ними договоры поручения;
- цели обработки и уведомление Роскомнадзора: сверить с тем, что у оператора уже есть в реестре.

## Репетиция запуска в Docker

Образ собран и поднят с нуля с базой в контейнере (`docker compose --profile local-db up`): база, миграции, первый администратор из переменных, сайт со сжатием brotli и кэшем, заявка с токеном статуса, вход в HR, выгрузка Excel, картинки бота (sharp в Linux), проверка здоровья контейнера (`healthy`). Данные и сессии переживают перезапуск и пересоздание контейнера приложения.

- В рабочий образ попадают только зависимости сервера (`hono`, `@hono/node-server`, `postgres`, `sharp`, `tsx`), сайт приходит собранным в `dist`. Образ весит около 480 МБ.
- В рабочей версии cookie входа в HR стоит с флагом `Secure`: панель работает только по HTTPS (Safari по `http://` его не примет). Ставьте сервер за прокси с HTTPS, см. «HTTPS и прокси».
- Если на машине уже занят порт 5432 (локальный PostgreSQL), задайте `POSTGRES_PORT`, например `POSTGRES_PORT=5433 docker compose --profile local-db up -d`.
- Для репетиции на своей машине подойдёт `SITE_URL=http://localhost:8787`: `http://` разрешён только для `localhost` и `127.0.0.1`.
- «Демо-данные» и «Очистить базу» в рабочей версии отключены; для демо-стенда нужен `HR_DEMO_TOOLS=1`.

## Демо-стенд для экспертов

Для проверки решения жюри нужен стенд, где HR-панель открывается без настоящих данных. Шаги:

1. Поднять образ, как в разделе выше, с переменными `HR_DEMO_TOOLS=1` и отдельным администратором для проверяющих: `HR_ADMIN_EMAIL=jury@<домен>`, `HR_ADMIN_PASSWORD=<пароль от 10 символов>`. Этот пароль только для стенда, в рабочей версии свой.
2. Войти в `/hr` этим администратором и нажать «Настройки → Данные → Демо-данные»: заявки, собеседования, день найма, ответы новичков «Как дела на смене», демо-ответы фокус-группы с подписью «Демо-ответы, не исследование».
3. Почту и пароль проверяющих передать вместе с решением. В открытый README пароль не кладём: сайт публичный, и на стенд могут прийти настоящие заявки.
4. Проверить вход с телефона и страницу `/materials`: все макеты открываются по ссылкам.
5. После проверки нажать «Очистить базу» и сменить пароль или снять стенд.

Боты, GigaChat, Диск и SMS на стенде не нужны: без ключей Квасыч отвечает офлайн-режимом, а сообщения кандидатам из бота видны во вкладке «Боты» как предпросмотр.

## Ограничения, о которых стоит знать

- Лимиты запросов хранятся в памяти процесса. При нескольких экземплярах приложения лимит считается на каждый отдельно; для сезонной нагрузки одного экземпляра достаточно.
- GigaChat на тарифе для физлиц принимает один запрос за раз, поэтому помощник ставит запросы в очередь. Для продакшна нужен договор с юрлицом.
- Сервер запускает TypeScript через `tsx`, поэтому в образе все зависимости. Если понадобится образ меньше, сервер можно собрать в один JS-файл.
