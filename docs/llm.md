# Квасыч-помощник: LLM на GigaChat

Квасыч отвечает на вопросы свободным текстом и подбирает работу по описанию. Модель работает поверх нашего ядра: цифры и вакансии она берёт из данных через функции и сама их не придумывает. Квасыч, бот «Очаково», это собирательный образ заводского наставника (`docs/brand/concept.md`, раздел 8): он подсказывает на сайте и в боте, а на заводе учит настоящий наставник.

## Принципы

1. **Кнопки и задания остаются без LLM.** Меню, «Поймай брак», «Собери лето», подбор работы, «Правда или миф» и заявка работают как детерминированные сценарии: быстро, бесплатно, без ошибок. LLM включается, когда человек пишет текстом.
2. **Факты только из базы.** Зарплаты, графики, адреса, условия и быт модель получает из `shared/`: «Описание практики», «Справочник студента», вакансии с hh.ru, история и бренды из каталога. Если ответа в базе нет, Квасыч честно говорит об этом и даёт контакт отдела подбора.
3. **Действие вместо пересказа.** Ответ заканчивается кнопками: открыть вакансию, посчитать заработок, начать заявку. Модель предлагает действие, а выполняет его наш сценарий.
4. **Один помощник везде.** Тот же код отвечает в Telegram, в MAX (когда бот будет подключён) и в чате на сайте через `/api/dialog`.
5. **Работает без ключа.** Без доступа к GigaChat включается офлайн-режим: правила по намерениям и поиск по базе знаний. Демо не ломается.
6. **HR дополняет базу без программиста.** Ответ отдела персонала на вопрос из «Вопросов к Квасычу» сразу становится ответом Квасыча.

## Что умеет

| Задача | Пример | Как работает |
|---|---|---|
| Ответ на вопрос | «Сколько платят на складе и есть ли ночные смены?» | функции `search_vacancies`, `get_vacancy`; ответ с цифрами из данных и кнопкой вакансии |
| Быт и правила по справочнику студента | «Сколько стоит общага?», «Потерял пропуск», «Телефон учебного центра», «Есть испытательный срок?» | общежитие, столовая, дни зарплаты, экзамены и отпуск, спецодежда и прачечная, пропуск, здравпункт, документы по практике, наставник, договор, корпоративный автобус, добавочные телефоны; прямой ответ первой фразой |
| Подбор по описанию | «Учусь на технолога, свободен с июня по август» | модель извлекает профиль (`save_profile`), ранжирует наш код, модель объясняет выбор |
| Расчёт денег | «Сколько заработаю за лето оператором?» | функция `calc_earnings` (до вычета и на руки); у оплачиваемой практики летом считаются июнь и июль, потому что она идёт до конца июля или середины августа |
| Про производство и компанию | «Что делают в лаборатории?», «Какие бренды у „Очаково“?» | база знаний: этапы «Пути кваса», история, бренды без алкоголя |
| Пробелы базы | вопрос, на который нет ответа | `escalate_to_hr` → запись без личных данных в `kb_gaps`; HR видит вопрос в «Вопросах к Квасычу» и отвечает на него там же. Тему берём из словаря (`server/assistant/topics.ts`), одинаковые вопросы разными словами попадают в одну строку |

## Ответы HR на «Вопросы к Квасычу»

Путь вопроса без ответа:

1. Человек спрашивает то, чего нет в данных («есть парковка для сотрудников?»). Квасыч отвечает «Точного ответа в моих данных нет. Спроси в отделе персонала», вопрос без телефонов и имён уходит в `kb_gaps`.
2. В HR-панели, раздел «Вопросы к Квасычу», у вопроса кнопка «Ответить»: текст ответа и, если нужно, другие формулировки, по одной в строке. Текст проверяется на лету (`POST /api/hr/kb-answers/check`):
   - без «!» и без дат: даты быстро устаревают, пишем «в сезон», «за две недели»;
   - личные телефоны, почта и имена вычищаются тем же фильтром, что вопросы (`redactPersonal`); общие контакты отдела подбора и почта для соискателей остаются. Если что-то вычистили, сохранение останавливается и HR видит текст, который сохранится;
   - про алкоголь Квасыч не говорит;
   - род проверяется подсказкой: «готов», «согласна», «(а)» не мешают сохранить, но панель предлагает нейтральную форму.
3. Ответ сохраняется в `kb_answers` (миграция `016_kb_answers.sql`), вопрос помечается «Разобрано», похожие открытые вопросы закрываются этим же ответом.
4. Ответы HR живут в отдельном маленьком индексе (`server/assistant/hrAnswers.ts`), общий индекс базы знаний не трогается. Квасыч проверяет его раньше правил и основной базы: совпадение по словам с весами, общие слова должны покрывать не меньше 60 % веса и вопроса, и формулировки HR. Поэтому «парковка у завода есть?» находит ответ на «есть ли парковка для сотрудников», а «сколько платят сотрудникам» его не находит.
5. В GigaChat ответы HR попадают разделом «Ответы отдела персонала» в конце базы знаний. Кэш текста базы и системного промпта сбрасывается по версии: начало промпта не меняется и остаётся в кэше GigaChat.
6. guard считает суммы, время и проценты из включённых ответов HR разрешёнными.
7. Ответ можно поправить или выключить. Выключенный ответ Квасыч не использует: на такой вопрос он снова советует отдел персонала, и вопрос снова попадает в «Вопросы к Квасычу».

Источник ответов задаёт `server/api/hr-kb.ts` при создании API: `setHrAnswerSource(fn)`. После правки индекс перечитывается сразу, в других процессах сервера не позже чем через минуту. Без базы данных (проверки, бот без сервера) индекс пуст.

API (`requireHr` на каждом маршруте): `GET /api/hr/kb-answers`, `POST /api/hr/kb-answers/check`, `POST /api/hr/kb-answers` `{gapId?, question, answer, variants[]}`, `PATCH /api/hr/kb-answers/:id` `{question?, answer?, variants?, enabled?}`. При ошибке проверки сервер отвечает 422 `{error:'validation', errors, hints, cleaned}`.

## Устройство

```
server/llm/
  provider.ts      интерфейс LlmProvider: chat(request) → ответ или вызов функции; request.signal задаёт общий срок ответа
  gigachat.ts      GigaChat: OAuth-токен с кэшем, очередь с пределом, срок ответа, ретраи, сертификат Минцифры
  offline.ts       режим без ключа: намерения (справочник студента, деньги, сроки, график) и поиск по базе знаний
  speech.ts        живая речь: сленг, опечатки на одну правку только к словам базы,
                   «привет» и «спасибо» в начале, деление составного вопроса
server/assistant/
  knowledge.ts     база знаний из shared/; rebuildKnowledge() пересобирает её после правки вакансий
  text.ts          слова вопроса для поиска: основы, синонимы, без общих слов
  hrAnswers.ts     маленький индекс ответов HR: setHrAnswerSource, matchHrAnswer
  kbAnswers.ts     ответы HR: проверка текста и хранение в kb_answers
  tools.ts         функции для модели: search_vacancies, get_vacancy, calc_earnings, get_stage,
                   get_contacts, save_profile, search_knowledge, suggest_action, escalate_to_hr
  assistant.ts     цикл: системный промпт + база + история → до 3 вызовов функций → ответ; срок ответа; метрики
  guard.ts         проверки ответа (ниже)
  topics.ts        темы «Вопросов к Квасычу» по словарю
server/api/hr-kb.ts  маршруты ответов HR
src/components/hr/KbGapsView.tsx, src/lib/hr/kb.ts  раздел «Вопросы к Квасычу» в панели
```

Сценарий бота (`server/dialog`) передаёт помощнику любой свободный текст вне сценариев. Помощник отвечает тем же `OutMessage`: текст и кнопки действий.

## База знаний

База небольшая, несколько тысяч токенов: практика и вакансии, условия, справочник студента, вопросы-ответы, этапы производства, история, бренды, контакты и ответы HR. Она целиком помещается в контекст, поэтому векторный поиск не нужен. Если база вырастет на порядок, подключаем эмбеддинги GigaChat и pgvector в том же Postgres; интерфейс `knowledge.search()` при этом не меняется.

После правки вакансий в панели вызывается `rebuildKnowledge()`: пересобираются фрагменты базы, текст для промпта, список вакансий в описании функций и разрешённые суммы guard. Квасыч называет новую сумму без перезапуска.

## Срок ответа

Человек не ждёт дольше срока: в ботах 25 секунд, на сайте 20 (чат на сайте ждёт 30). Срок общий и включает очередь к GigaChat:

- запрос, который ждёт в очереди, снимается из неё, когда срок вышел, и место переходит следующему;
- `AbortSignal` прерывает сам запрос и паузу перед повтором; внутри срока повтор один (без срока до трёх при 429, 5xx и сетевых ошибках);
- если в очереди уже ждут `GIGACHAT_QUEUE` запросов (по умолчанию 8), новый сразу получает офлайн-ответ;
- после срока или при полной очереди отвечает офлайн-режим по той же базе (`source: 'fallback'`), в журнале появляется строка «таймаут…».

Для `/api/health` есть `assistantStats()`: число ответов, средняя задержка, доля запасных ответов (guard и fallback), число таймаутов.

## guard: что проверяем в ответе

Всё, что модель называет, должно быть в базе знаний, в ответах HR или в расчёте `calc_earnings` этого ответа:

- суммы в рублях (зарплаты, на руки, за смену и в час, общежитие 3 400 и 6 800 ₽, штраф за пропуск);
- время суток («8:00», «с 8 до 20») только из графиков и справочника;
- проценты только из базы: НДФЛ 13 % и 50 % оплаты общежития;
- дни выплат только 12-го и 27-го;
- интервалы «каждые N минут» не пропускаем: расписаний в данных нет;
- «бесплатно», «за счёт компании», «оплачивает завод» рядом с общежитием, медкнижкой, проездом и едой не пропускаем. Правда только «медосмотр и спецодежда за счёт компании» и «половину стоимости оплачивает компания». «Бесплатная практика» называет формат практики, её не трогаем;
- про ДМС только «не указан»: в материалах «Очаково» его нет;
- должности только из вакансий (честный ответ «вакансии грузчика нет» пропускаем), без обещаний «точно возьмут», без алкоголя.

Ответ, который не прошёл проверку, заменяется офлайн-ответом (`source: 'guard'`). Каждая фраза базы знаний проходит guard, это проверяет тест.

## Ограничения и безопасность

- Отвечает только про работу в «Очаково». Посторонние темы мягко возвращает к практике и вакансиям, в отдел персонала их не передаёт.
- Не обсуждает пиво и алкоголь, аудитория 18–26 и бренд работодателя.
- Персональные данные в модель не отправляем: имя и телефон собирает только сценарий заявки, а перед отправкой текст очищается от телефонов, почты, ников и имени. Для физлиц это требование соглашения GigaChat.
- Вопросы без ответа логируются без персональных данных.

## GigaChat: как подключаем

Проверено по документации Sber (developers.sber.ru/docs/ru/gigachat):

- **Доступ.** Ключ авторизации выдаёт GigaChat Studio (вход по Сбер ID). Для физлиц есть scope `GIGACHAT_API_PERS`, только для некоммерческого использования. Для «Очаково» в продакшне нужен корпоративный договор (`GIGACHAT_API_CORP`).
- **Токен.** `POST https://ngw.devices.sberbank.ru:9443/api/v2/oauth` с `Authorization: Basic <ключ>`, `RqUID` и `scope`. Токен живёт 30 минут: держим в памяти, обновляем за минуту до истечения, при 401 обновляем один раз и повторяем.
- **Запросы.** `POST https://api.giga.chat/v1/chat/completions`, `Authorization: Bearer`. Нужен сертификат «Russian Trusted Root CA», сервер запускаем с `NODE_EXTRA_CA_CERTS` (тот же файл, что для MAX).
- **Модели.** `GigaChat-2` извлекает профиль и выбирает функцию, `GigaChat-2-Pro` отвечает человеку.
- **Функции.** Формат `functions` с JSON-схемой и примерами запросов. Ответ модели с `function_call` возвращаем в историю вместе с `functions_state_id`, затем результат с ролью `function`.
- **Кэш.** База знаний идёт неизменным системным промптом с постоянным `X-Session-ID` на диалог, чтобы повторные токены не оплачивались.
- **Нагрузка.** Для физлиц разрешён один одновременный запрос (`GIGACHAT_CONCURRENCY=1`), все вызовы идут через общую очередь длиной `GIGACHAT_QUEUE`. Таймауты: токен 10 с, отдельный запрос 60 с, ответ человеку по сроку выше.
- **Модерация.** Ответ с `finish_reason: blacklist` (в том числе темы алкоголя) заменяем готовой фразой и предложением вернуться к вакансиям.

Переменные: `GIGACHAT_AUTH_KEY`, `GIGACHAT_SCOPE`, `GIGACHAT_MODEL_FAST`, `GIGACHAT_MODEL_ANSWER`, `GIGACHAT_BASE_URL`, `GIGACHAT_CONCURRENCY`, `GIGACHAT_QUEUE`.
